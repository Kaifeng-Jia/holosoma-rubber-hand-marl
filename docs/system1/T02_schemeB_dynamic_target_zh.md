## 思路

SONIC 只跟踪位置，没有力的接口，所以在规则层面能做的有两件事：
1. 让手的目标跟着物体的实际位置走；
2. 把手的目标往物体里面放一点，用跟踪误差产生压紧力。

不训练任何东西。

## 适用任务

- 有手部交互的五个任务：Table Pushing、Table Pulling、Chair Righting、Bin Transport、Table Transport。
- Table Kicking 用脚交互，标为"不适用"，不跑。这和论文对 Kicking 的处理一致。

## 规则（每个控制步、每台机器人）

1. **离线预计算（只做一次，结果存文件并记 sha256）：**
   - 对参考的每一帧，计算左右手在物体坐标系下的位置 `p_ref^o`。手的取点与论文手误差的取点相同。
   - 计算从手指向物体表面最近点的单位向量，在物体坐标系下记为 `n_ref^o`。用物体碰撞网格计算。
   - 计算接触标志：参考里手到物体表面的距离小于 3 cm 记为 1，否则记为 0。
2. **在线：** 手的世界坐标目标为
   `p_tgt = T_obj_actual · p_ref^o + δ · c · (R_obj_actual · n_ref^o)`
   - `T_obj_actual`、`R_obj_actual` 是物体当前的实际位姿和旋转；
   - `c` 是接触标志；
   - δ 是偏移量。
3. **手臂 IK：**
   - 只解两条手臂各 7 个关节。用阻尼最小二乘，基座取机器人当前的实际位姿，初值取参考的手臂角度。
   - 每步迭代次数固定，并截断到关节限位。
   - 其余关节用参考值。
   - 修改后的关节参考交给 SONIC。SONIC 编码器要看的未来窗口，用同样的规则逐帧修改，并记录具体做法。
4. **偏移量：** δ 取 0、2、4 cm 三档，全部评测、全部报告，不挑。δ = 0 就是只做物体跟随。
