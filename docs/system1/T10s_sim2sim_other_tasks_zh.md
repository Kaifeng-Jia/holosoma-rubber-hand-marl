# T10 补充：其余任务的 MuJoCo sim2sim（2026-11-20 第一版）

## 目的

T10 只做了 Table 和 Bin。这次补上其余任务，看哪些任务能迁到 MuJoCo、哪些不能：
- D 的 Push、Pull、Kick、Chair；
- C-in 的 Pull。

**设置完全沿用 T10，不改任何接触或关节参数。** 改接触参数的敏感性测试另做，等 Kevin 同意。

## 事先写下的判断（不据此挑选结果）

T10 里，失败集中在靠手夹持的阶段。Push 和 Kick 主要靠推挤接触，预计掉得比靠夹持的任务少。Pull 和 Chair 是否靠夹持，看结果再说。所有回合照实报告。

## 范围

| 方案 | 任务 | 种子 | 低层设置 |
|---|---|---|---|
| D | Push、Pull、Kick、Chair | 721、722、723 | 论文设置 |
| C-in | Pull | 721、722、723 | 和 T10 一样两种：(i) Isaac 训练时的 PD；(ii) 官方部署的 PD 和力矩上限 |

- 每组都跑 ±2、±8 两档，各 50 个回合，nominal 单独列。
- **只用 CPU 和本机。** 用 5070 的只有两件事：Isaac 导出场景，以及渲染。T09 如果还在跑，优先给 T09。
- **通过后直接继续，做完交付。**

## 步骤（和 T10 相同，逐任务做）

1. **导出场景。** 用 `--sim2sim-dump`，从和 5070 最终评测完全相同的场景里导出 PhysX 的实际参数，每个任务一份。重跑 nominal 回合，和已保存的轨迹逐元素比较。
2. **MuJoCo 场景。** 用 T10 的 `system1/sim2sim/` 生成，物体按各任务的 PhysX 导出建：碰撞形状、质量、惯量、摩擦组合方式。
3. **初始状态核对。** 冻结状态文件按 sha256 核对；加载后的差值阈值和 T10 第 1 步相同（1e-4）。
4. **观测核对。** 每个任务取 D 种子 721 的 nominal 回合，逐维比较 158 维观测，阈值 1e-4。C-in Pull 另外核对 SONIC 的两路输入。
5. **ONNX 核对。** 按 T10 的做法：float64 计算图和 PyTorch 的差 ≤ 1e-10 算通过；float32 的差只报告，不作为停止条件。
6. **开环回放 1 秒。** 每个任务一个 nominal 回合，只报告。
7. **闭环评测。** 协议和 T10 第 3 步相同，不调参。

**失败分析：** 每个任务写明终止原因的计数，以及物体误差开始分开的大致步数和对应阶段（例如"抬起""交接""推行"）。只写观察到的事实。

**视频：** 每个任务的 D 种子 721 nominal 回合，Isaac 和 MuJoCo 各渲染一段，只留本地 `exports_system1/t10/videos/`。

做完 push，按常规格式回报。
