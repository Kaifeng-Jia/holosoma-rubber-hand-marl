# T05：物体尺寸扫描（2026-11-09）

## 目的

看四种方案各自能应付多大的物体。只改物体尺寸，质量不变。

## 设置（事先定）

- **任务：** Table Transport。
  - 双人示范，用共享场景生成参考；
  - 桌子尺寸变了，两台机器人的站位会跟着变。
- **尺寸：** 物体几何整体缩放 s = 0.8、1.2 两档；s = 1.0 是现有的点。
- **质量和惯量：** 质量固定 5 kg；惯量按新几何重新计算，质量固定时惯量与 s² 成正比。

## 第一阶段：生成参考（只用 CPU，现在就可以开始，与其他任务并行）

1. **找生成链路。** 在代码地图的基础上，找出论文 Table 参考（`core4d_pair_runtime_fps50.npz`，sha256 `582e7669…`）的完整生成链路，包括命令、配置和中间文件。
2. **重生成验证（门槛）。**
   - 用同一链路和同一命令，在 s = 1.0 时重新生成一次。
   - 结果必须与论文参考一致：sha256 相同，或逐帧最大差小于 1e-6。
   - 不一致就停下回报。
3. **生成两个新尺寸的参考。**
   - 在这条链路里加一个物体缩放开关，开关关闭时行为不变。
   - 用它生成 s = 0.8 和 s = 1.2 的参考。
   - 如果现有链路无法处理缩放后的物体，改用论文里"按原物体重新优化两人动作"的模式，并说明原因。
4. **参考质量检查。** 每个尺寸报告下面几项，并与 s = 1.0 并列：
   - 接触期间手到物体表面的距离；
   - 穿透深度；
   - 脚滑（口径与 T01b 漂移分析相同）；
   - 两台机器人之间的距离；
   - 参考时长。
5. **冻结初始状态。** 按论文规则为两个新尺寸生成 ±2 和 ±8 的初始状态文件：
   - 生成种子 241003；
   - ±8 档由 ±2 档的同一组均匀抽样乘以 4 得到；
   - 记录 sha256。

第一阶段做完先交返包，然后停下等回复。第二阶段要等新版 T02 定稿，并且云端有空闲 GPU。

## 第二阶段（第二波）

- **A、B：** 两个新尺寸直接评测，不训练。
- **D、C：** 每个新尺寸各训练一个 run，种子 721，共 4 个。
  - 配置与该任务的 T04 D 部分和 T03 相同，只换参考、物体和初始状态文件。
- **评测：** 协议与方案 A 相同。
