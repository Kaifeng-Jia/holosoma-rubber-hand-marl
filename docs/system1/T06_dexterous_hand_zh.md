# T06：Sharpa 灵巧手扩展（2026-11-13 第一版）

**状态：** Kevin 已确认推进。第 0–2 步现在就做；第 3 步训练要等云端 GPU 和 Kevin 的开训指令。

## 目的

在 Bin Transport 一个任务上，让 D 的策略同时控制身体和灵巧手的手指（老师：手指"要策略的"）。原来列的三件事里，第 3 件（锁死对比）只作为讲法，不做实验：
1. 同一套框架，把橡胶手换成灵巧手（Sharpa Wave）后仍然能用。
2. 手指怎么接触物体，完全由物体几何优化得到，不用人手数据（retarget-free）。有人手数据时，可以按比例混合进来，而不是二选一。
3. 橡胶手相当于"手指锁死的灵巧手"，是灵巧手的一个特例。

**范围：**
- 只做方案 D，也就是端到端的 DuetMimic；不改 A、B、C。
- 只做 Bin 一个任务。
- 不改 T03、T04 正在进行的任何东西。本机最终评测的优先级始终高于本任务。

## 第 2 步：retarget-free 的手指参考

**身体部分：** 沿用现有 Bin 参考的身体关节和物体轨迹，只用 Sharpa 的掌面坐标系重做一次腕部优化。方法和原来相同，只换手的几何。

**手指部分：** 逐帧优化手指关节 q_f。
- **接触帧**（手到物体表面的距离小于阈值，定义同现有流程）的目标函数：
  - 手指和手掌上采样点到物体表面的距离（希望贴合）；
  - 穿插惩罚（有符号距离小于 0 的部分）；
  - 关节限位；
  - 相邻帧平滑；
  - 向张开姿态的正则。
- **非接触帧：** 手指取自然张开的姿态。
- **过渡：** 接触开始和结束前后各用约 0.2 s 平滑过渡。
- **混合旋钮（"中和"）：**
  - 目标函数里预留一项 w·‖q_f − q_f^人手‖²；
  - 没有人手数据时 w = 0。本任务默认 w = 0。
  - 第 0 步如果确认 Bin 有可用的人手数据，就另外生成一份 w > 0 的参考，作为演示，不训练。
- **锁死模式参考：** 手指固定在一个张开的姿态，只做腕部优化。这就是"锁死的灵巧手"。
- **核查：**
  - 每帧的手–物最大穿插和接触点数；
  - 手指关节是否在限位内；
  - 一张关键帧拼图（Unitree 原色，同 Fig. 4 风格），能看清手指怎么搭在桶沿上。
- **门槛（2026-11-13 修订，替换原"穿插不超过 1 cm"）：**
  - 原门槛没过。原因是手掌位置由身体参考决定，而原 D 橡胶手参考本来就插进桶网格最深约 9.9 cm（`results_system1/T06/step2_gate/`）。
  - Kevin 选方案 A：
    - 接触帧按机器人手的几何判定，不再用人手掌点的距离；
    - 所有帧都加穿插惩罚；
    - 手掌组（手掌 + 拇指掌骨 thumb_MC）的穿插单独报。
  - 不做 B（改手臂关节），不换空心桶（C 留到以后）。
  - 新门槛：
    1. 手掌组每帧的穿插，不超过同一帧原 D 橡胶手参考的穿插；
    2. 其余手指的穿插不超过 1 cm；
    3. 按机器人手判定的接触帧里，至少 80% 满足"手掌 + 至少 2 根手指"接触；
    4. 关键帧拼图（Unitree 原色）提交后停下，Kevin 看过点头。

  不过就停下回报，不自行改规则。

- **门槛第二次修订（2026-11-13 15:30，看过方案 A 的结果之后）：**

## 第 3 步：训练（等云端 GPU 和 Kevin 的开训指令）

加开关 `--finger-mode {locked, track, learn}`，三种都实现。默认关闭时，行为和现在的橡胶手完全一样。

| 模式 | 手指 | 策略动作 |
|---|---|---|
| locked | 固定在张开姿态 | 29 维（同 D） |
| track（不学） | PD 跟踪第 2 步的手指参考 | 29 维（同 D） |
| learn（学，主方案） | 第 2 步的手指参考 + 策略输出的修正 | 29 + 44 维 |

- **learn 模式的修正（2026-11-13 修订：老师回复手指"要策略的"）：**
  - 手指动作的处理和 D 的身体动作完全一样：
    - 缩放按 holosoma 的规则算（0.25 × 力矩上限 / Kp），用 Sharpa 的参数；
    - 截断用 D 的设置，不再限制在 ±1；
    - 区别只在零点：D 的零点是默认姿态，这里是第 2 步算出的几何握法。
  - 最后截断到手指关节限位。
  - 修订原因：按规则算出的手指缩放只有 0.05–0.18 rad。若再限制在 ±1，手指只能偏离几何握法 3–10°，学了几乎等于没学。手指直接驱动关节，梯度不像 T03 C 第一版那样要先经过 SONIC；而且物理上被关节限位卡住，不会出现那种失控。
  - 手指那部分输出层初始化为 0，所以第 0 轮和 track 模式完全一样。
  - 训练诊断另记：手指修正的大小、顶到关节限位的比例、手指部分的动作标准差。
- **观测：** 三种模式都在 D 的 158 维之外，加上本机器人两只手的手指关节位置，以及手指参考目标。三种模式的观测相同，只有动作不同。
- **奖励、终止、MAPPO 超参数、并行环境数、迭代预算：** 与 D 的 Bin 主结果相同（从零训练 12000 轮，actor 学习率 1e-3）。奖励不加手指项。
  - 显存放不下 2048 个环境时，先停下回报，不自己改。
- **开训（2026-11-13 修订）：** 按老师的意思，手是方法本身的一部分，不做对比。只训 learn，Bin，种子 721、722、723。locked 和 track 保留在代码里，只用于调试，不训练。
- **开训前：** 冒烟 10 轮；第 0 轮的 learn 与 track 一致；逐字段比对 run_config 和 D 的 Bin 配置，diff 随交付提交。
- **训练诊断：** 同 T03 第二版，每 100 轮记一次，learn 模式另记手指修正的大小和截断比例。
