# 论文结果的组织方案和对比规范（2026-11-13 第一版）

目的：
- 每一项对比都按学术界通行的做法来做，做不到的地方照实写成局限；
- 事先定好结果出来后怎么放进论文，避免看了结果再挑比法。

本文件是总纲，具体执行看各任务书（T03、T04、T06）。

## 一、论文要回答的问题

面向交互的多机器人快系统（System 1）该怎么搭：交给通用全身控制器（分层），还是端到端学？答案落在"什么条件下用哪种"。

五种执行方式排成一列，学习介入得越来越深：

| 方案 | 做法 |
|---|---|
| A | 参考直接交给 SONIC |
| B | 规则修正目标 |
| C-in | 学习修正 SONIC 的输入 |
| C-out | 学习修正 SONIC 的输出 |
| D | 端到端（DuetMimic） |

相邻两种只差一件事。所有方案共用：同一份参考、机器人、物体、冻结初始状态、终止条件和指标。

**同一个问题在手上再问一次（2026-11-13 修订：灵巧手不是附加的"扩展"，而是主线的第二层）：** 手指也排成一列，学习介入得越来越深：

| 方案 | 手指 |
|---|---|
| locked | 锁死，相当于橡胶手 |
| track | 跟着几何算出的握法，不学 |
| learn | 交给策略学 |

- 身体这一层问的是"学习要不要伸到关节、要不要绕过通用控制器"；手这一层问的是"学习要不要伸到手指，还是几何就够了"。
- 两层合起来回答"学习至少要介入到哪一层"。
- 方法上，手的接触由物体几何决定，不需要人手数据，所以同一套流程适用于橡胶手和灵巧手，有人手数据时可以按比例掺入。

## 二、每一项对比的规范

### 1. 主对比：原质量下的完成率

- **协议：**
  - 每个任务 50 个冻结初始状态，分 ±2、±8 两档；确定性动作；TF32 关闭；
  - 全部在同一块卡（本机 5070）上评测；
  - 最终 checkpoint，不挑选。
- **种子：**
  - D 和 C-in 各 3 个种子，报均值 ± 标准差；
  - C-out 目前只有 1 个种子，标"单种子"；
  - A、B 是确定性的，不训练，没有种子。
- **统计：** 每个种子与 D 按初始状态配对，做精确 McNemar 检验，每个 p 值都报，这是预登记的口径。
- **任务范围：**
  - A、B、D 做全部任务；
  - C 只做 Pull、Table、Bin，覆盖拖、抬、举起交接三类交互。理由（算力）写进正文。
- **必须写明的差异：**
  - SONIC 方案的髋关节 pitch 增益用 SONIC 的值（T01b 做过敏感性评测）；
  - C-in 的探索设置和 D 不同，按文献里在跟踪器上做强化学习的做法设定；C-out 和 D 相同；
  - C-in 有 13%–21% 的修正量顶在上限上。

### 2. 训练效率

- **协议：** 完成率随训练环境步数变化的曲线。每 1000 轮（D 的 Table、Bin 每 2000 轮）一个 checkpoint，在 ±2 档上评测。曲线的点全部用云端 4090 评测。
- **种子：** C-in 和 D 各 3 个，画均值和范围；C-out 1 个。
- **对照：**
  - Pull 要同时对比 D 从零训练（V3-25–27）和 D 带单人先验（论文主结果）；
  - Table、Bin 的 D 本来就是从零训练。
- **指标：** 首次达到 50%、80% 完成率的环境步数，以及曲线下面积。另报每轮的墙钟时间和 GPU 型号：SONIC 推理有额外开销。
- **必须写明：** C 借助了预训练的 SONIC。SONIC 自身的预训练代价不计入比较，这正是"分层"能省事的原因，正文要说清楚，不回避。

### 3. 承重边界

按 T04 第四版补充执行：
- **主结果：** 每个较重档位各自重训一个策略（D 和 C-in，种子 721）。横轴是"原质量的几倍"。
- **边界的定义：** ±2 档完成率不低于 50% 的最大质量。
- **补充规则：** 加档和插档规则见 T04；物理上做不到的档位标"超出物理上限"，不用来比较架构。
- **机制：** 关节力矩顶到上限的比例。
- **局限：** 只有 1 个种子，照实写。A、B 在所有档位都是 0，只在表里列一行。

### 4. 鲁棒性

- **主要指标：** ±8 档的完成率（更大的初始扰动）。这是通行做法。
- **补充：** 原质量的策略直接评其他质量（不重训），反映对质量变化的敏感度。
- **换卡翻转：** 只进附录，作为评测本身的不确定性说明，不作为鲁棒性的论据。

### 5. 手这一层（T06）

- **范围：** 身体用 D，任务用 Bin。Bin 是需要举起和交接的任务，手的作用最大。
- **种子（待 Kevin 确认算力）：** locked、track、learn 各 3 个种子，与橡胶手的 D 并排。三层都有 3 个种子，才能像身体那一层一样比较。
- **讲法：** 手的接触由物体几何决定，不需要人手数据；橡胶手是手指锁死的特例。
- **可选（算力够时）：** learn 和 track 在 Bin 较重档上各重训一个，检验"手指没劲"在承重上的体现。

## 四、正文的结论怎么写（按结果填，不预设）

| 结论 | 状态 |
|---|---|
| 不学习不行：A、B 在所有任务和质量上几乎全部失败；原因是没有全局位置反馈导致落后，以及姿态（弯腰）跟不上接触 | 已有结果 |
| 在通用控制器上学一层训练最快：C-in 的训练效率明显高于从零训练的 D | 3 个种子出来后定稿 |
| 大扰动下 C-in 最弱，C-out 和 D 接近 | Pull 已有；Table、Bin 待出 |
| 承重：看重训结果和物理上限核算 | 待出 |
| "什么时候用哪种"的边界 | 由以上几条合成 |

**用词约束：**
- 不写"更好"这种笼统的话，只写在哪个维度、哪个条件下更好；
- 单种子的结果写"初步"；
- 只在仿真中，真机放到局限里。
