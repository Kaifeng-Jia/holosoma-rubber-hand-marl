# T03：方案 C，MARL + SONIC（2026-11-09 第二版）

**开始条件：** T01b 第一节（F1–F6）全部通过，云端 GPU 可用。可以和方案 A、B 的评测并行。

## 设计

C 和 D 只差一处：策略的输出是直接作为关节目标（D），还是先作为修正量交给 SONIC，再由 SONIC 输出关节目标（C）。其余一律相同。

- **动作：**
  - 每台机器人的网络输出 29 维 a，修正量 Δq = 论文 D 的动作缩放 × a（按 F2 冻结）。
  - Δq 加到参考的关节角上，再交给 SONIC。SONIC 编码器要看的未来窗口（10 帧），每帧都加同一个 Δq。
  - 输出层权重和偏置初始化为 0，所以第 0 次迭代时 C 和方案 A 完全一样。
- **SONIC：** 冻结，只推理、不求梯度。按环境重置（F5）。TF32 在训练时可以打开，评测时关闭。
- **观测：**
  - actor 用 D 的 158 维观测，代码路径相同；critic 也和 D 相同。
  - 其中"上一步动作"一项，取 C 自己上一步的网络输出 a（未乘缩放），与 D"看到自己上一步的输出"同理。
- **奖励：** 与该任务的 D 相同，包括 reward variant。
  - 动作变化惩罚按物理关节目标 q* 计算，换算用论文 D 的动作缩放。这样它的物理含义和 D 一样。
- **终止、MAPPO 超参数、并行环境数、每次迭代步数：** 与下表的对照组逐项相同。
- **初始化：** actor 从零开始，因为单人先验的动作含义不同，不能直接用。

## 种子与剔除

- **种子：** 三个任务先各跑 721；三个都跑通后，各补 722、723。补种子是事先定好的，不看结果决定。
- **剔除规则（事先定）：** 只有出现 NaN/Inf，或进程中断且无法从 checkpoint 续训，才算无效。无效的用同一个种子重跑一次；仍然无效就换下一个种子号，并写明原因。

## 每次开训前

- 跑 smoke test：10 次迭代不报错；第 0 次迭代的 rollout，与方案 A 在同一初始状态下的轨迹一致（TF32 关闭）。
- 对 run_config 做逐字段 diff，对照上表。只允许与"动作经过 SONIC"相关的字段、种子、目录、时间戳不同。diff 随交付提交。

## 训练速度（预登记口径）

- **checkpoint：** 每 1000 次迭代存一个。
- **主指标：** 在该任务冻结的 ±2 档 50 个初始状态上，对每个 checkpoint 做确定性评测（TF32 关闭）。
  - 画"完成率–迭代数"曲线。
  - 报告首次达到 50% 和 80% 完成率所需的迭代数和环境步数；没达到的写"未达到"。
  - 报告曲线下面积。
- **D 的同口径曲线：** 用已存下的 checkpoint 评测，不重训。
  - Pull：V3-25–27 和论文主结果，每 1000 次存一个；
  - Table、Bin：论文主结果，每 2000 次存一个。按实际存在的 checkpoint 评测，并在表里注明间隔不同。
- **辅助指标：**
  - 奖励中跟踪部分（身体加物体）的曲线，不含正则项；
  - 每次迭代的平均秒数和 GPU 小时，注明 GPU 型号，和同型号 GPU 上的 D 训练比较。
