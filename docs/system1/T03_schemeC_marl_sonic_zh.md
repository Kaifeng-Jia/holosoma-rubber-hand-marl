# T03：方案 C，MARL + SONIC（2026-11-09 第二版）

**开始条件：** T01b 第一节（F1–F6）全部通过，云端 GPU 可用。可以和方案 A、B 的评测并行。

## 设计

C 和 D 只差一处：策略的输出是直接作为关节目标（D），还是先作为修正量交给 SONIC，再由 SONIC 输出关节目标（C）。其余一律相同。

- **动作：**
  - 每台机器人的网络输出 29 维 a，修正量 Δq = 论文 D 的动作缩放 × a（按 F2 冻结）。
  - Δq 加到参考的关节角上，再交给 SONIC。SONIC 编码器要看的未来窗口（10 帧），每帧都加同一个 Δq。
  - 输出层权重和偏置初始化为 0，所以第 0 次迭代时 C 和方案 A 完全一样。
- **SONIC：** 冻结，只推理、不求梯度。按环境重置（F5）。TF32 在训练时可以打开，评测时关闭。
- **观测：**
  - actor 用 D 的 158 维观测，代码路径相同；critic 也和 D 相同。
  - 其中"上一步动作"一项，取 C 自己上一步的网络输出 a（未乘缩放），与 D"看到自己上一步的输出"同理。
- **奖励：** 与该任务的 D 相同，包括 reward variant。
  - 动作变化惩罚按物理关节目标 q* 计算，换算用论文 D 的动作缩放。这样它的物理含义和 D 一样。
- **终止、MAPPO 超参数、并行环境数、每次迭代步数：** 与下表的对照组逐项相同。
- **初始化：** actor 从零开始，因为单人先验的动作含义不同，不能直接用。

## C 第二版（2026-11-11，第一版训练发散之后；同日查文献后修订）

### 背景

第一版的训练诊断（`results_system1/T03/c_learning_diag_20261111/`）显示：
- 代码路径按设计执行，交给 SONIC 的参考与"参考 + 缩放 × a"逐位相同；
- 但动作没有上下限。Δq 的均值到第 4000 轮已达 3–14 rad，95 分位 40 rad，最大 104 rad；动作标准差从 1.0 升到 2.9–6.5；
- SONIC 收到的参考已经失去物理意义，训练奖励不升反降。

### 第一版怎么处理

- 9 个第一版 C run（主实验 3 个、质量扫描 6 个）按 Kevin 的决定停止，日志和 checkpoint 全部保留。
- 结果如实报告为"C 第一版：残差无界，训练发散"，附诊断数据和已有曲线，以及停止时 checkpoint 的 ±2 评测。

### 参考了哪些做法

在冻结的通用跟踪器上训练强化学习策略，常见的有两种接法：
- **改跟踪器的输入（指令）。** VisualMimic（arXiv 2509.20322）的高层输出关键点指令，交给冻结的跟踪器执行，并把输出截断到跟踪器训练时见过的输入范围（μ ± 1.64σ）。文中写明：不截断时，高层探索出这个范围，训练就不稳定；截断能显著稳定训练。我们第一版的发散就是这种情况。MotionPyramid（arXiv 2606.20705）在冻结的运动先验上做潜空间残差，探索噪声固定为较小值（log std = −1.0）。
- **改跟踪器的输出（关节目标）。** ResMimic（arXiv 2510.05070）在 G1 上把冻结的通用运动跟踪策略作为基础，残差直接加在它输出的关节目标上，输出层初始化接近 0，用于全身移动操作。它的成功率远高于基础策略单独执行、从零训练和直接微调。MOSAIC（arXiv 2602.08594）用同样的接法。
- **SONIC 论文（arXiv 2511.07820）本身没有在 SONIC 上训练强化学习的实验。** 它的 VLA 输出 SONIC 的潜空间 token，不走关节参考。

据此，第二版分两种 C，原定的 C2a 取消。这个决定在任何第二版结果出来之前做出。

### 两种 C（都与第一版共用奖励、观测、终止、学习率规则、并行环境数、迭代预算和种子 721）

1. **C-in：修正 SONIC 的输入参考（原 C2b）。**
   - 环境侧把网络输出 a 截断到 [−1, 1]，Δq = 论文 D 的动作缩放 × a，所以 |Δq_i| ≤ scale_i；
   - "参考 + Δq"再截断到关节限位，之后才交给 SONIC；
   - 初始动作标准差 0.3，熵系数 0；
   - 策略的对数概率按未截断的 a 计算；"上一步动作"观测用截断后的 a。
2. **C-out：修正 SONIC 的输出关节目标（ResMimic 的接法）。**
   - SONIC 的输入是未经修改的参考，与方案 A 相同；
   - 最终关节目标 q* = SONIC 输出的关节目标 + 论文 D 的动作缩放 × a，交给 PD；
   - 动作的处理（截断、初始标准差、熵系数）与该任务的 D 对照组完全相同；
   - 输出层初始化为 0，所以第 0 轮的确定性 rollout 与方案 A 相同；
   - "上一步动作"观测取 C-out 自己上一步的 a；动作变化惩罚按 q* 计算，换算用论文 D 的动作缩放。
   - 与 D 只差一处：关节目标多了 SONIC 的输出作为基础。
- ResMimic 另用了接触奖励和"虚拟物体力"课程。C-out 不用，因为奖励和终止必须与 D 相同。

### 开训前检查

- 两种 C 都跑冒烟测试 10 轮，不报错。
- 第 0 轮的确定性 rollout 与方案 A 在同一初始状态下一致。
- C-in：用本机复现脚本核对 |Δq_i| ≤ scale_i，并核对交给 SONIC 的关节参考在限位以内。
- C-out：核对 q* 与"SONIC 输出 + 缩放 × a"的最大差为 0。
- 在 README 里列出每个关节的 scale_i（rad 和度），以及 D 对照组的动作截断设置。实现时优先复用 holosoma 现有的参数；没有的，再按开关的方式新加。

### 修正量有没有用的检查（诊断，不挡开训）

- 只做 Pull，用方案 A 的评测流程，在参考上加一个常数 Δq：髋和腰往"躯干更前屈、手更低"的方向，各取 0.5 倍和 1.0 倍上限，其余关节为 0；±2 档 50 个状态。
- 报告手相对桌腿顶部的高度、推动比例、完成率和摔倒率，与 Δq = 0 对比。
- 这项只作诊断，不算一个方案。

### 训练中要记录的诊断（第一版缺这几项）

用诊断开关写进训练日志，每 100 轮记一次：
- 修正量的均值、95 分位和最大值：C-in 记 Δq，C-out 记缩放 × a；
- 动作被截断的比例：|a| > 1 的维度占比；
- 动作标准差；
- SONIC 摔倒判定的触发率；
- 终止原因按物体位置、物体姿态、机器人躯干三项分开计数。

### 提前停止、质量扫描（事先定）

- **第 1000 轮检查：** 对每一种 C 分别检查。如果它的 3 个 run 里，没有任何一个 run 的第 901–1000 轮平均回合长度或平均 mean_step_reward 高于它自己第 1–100 轮的平均，就停掉这一种的 3 个 run，数据保留，并回报。
- **主实验：** 没有停的那一种 C 都训完全部预算。两种都报告，不在两者之间挑一个。
- **质量扫描用哪一种：** 两种都到第 2000 轮时，逐个任务比较 mean_step_reward（各取第 1901–2000 轮平均）。在三个任务中胜出更多的那一种，做 T04 的 C 质量扫描：6 个 run，配置同这一种，只改质量。不跨任务求平均，因为各任务的奖励量级不同。
  - 只有一种没停的，就用这一种。
  - 两种都停了的，不做 C 质量扫描，回报。
- 评测和训练速度的口径同前文。
