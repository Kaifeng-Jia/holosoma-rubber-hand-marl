# System 1 对比实验总览（2026-11-09 第二版）

## 要回答的问题

面向交互的多机器人快系统该怎么搭：
- 分层：目标交给通用全身控制器执行；
- 端到端；
- 两者结合。

要回答的是，每种方式在什么条件下够用、在什么条件下不够。

## 四种方案

| 方案 | 关节目标由谁给 | 是否训练 | 反馈 |
|---|---|---|---|
| A 静态目标 + SONIC | SONIC | 不训练 | 无，开环 |
| B 动态目标 + SONIC | SONIC | 不训练 | 规则闭环 |
| C MARL + SONIC | SONIC | 训练高层 | 学习闭环 |
| D 端到端 MARL | 策略本身 | 训练 | 学习闭环 |

- **A：**
  - 每台机器人各用一个 SONIC 实例，G1 编码器，权重共享、批量推理。
  - 输入是该机器人的 DuetMimic 参考。SONIC 不观测物体。
- **B：**
  - 用规则修正目标，让目标跟着物体的实际状态走，并把手的目标往物体内侧偏一段距离。
  - T01 发现 SONIC 跟踪我们的参考时根部会漂移，所以新版 B 会用 SONIC 的运动学规划器修正根部位置。任务书在 T01b 摸底之后发。
- **C：** 用 MAPPO 训练高层，输出对 SONIC 输入目标的修正量，SONIC 冻结不动。见 T03。
- **D：** 现有 DuetMimic，直接用论文的 checkpoint 和训练记录。

## 全部 SONIC 方案的共同约定

- **PD 增益：** 只把 hip_pitch 换成 SONIC 的值。动作缩放保持论文的值（F2）。
- **机器人模型：** 力矩上限等保持我们的。hip_pitch 的敏感性另做一组评测，见 T01b。
- **TF32：** 正式评测时关闭（F3）。
- **物理后端：** 一律 GPU PhysX，与论文 D 相同。

## 评测与指标

- **评测协议与论文相同：**
  - 每个任务 50 个冻结初始状态，分 ±2、±8 两档，另加 nominal 一个回合；
  - 确定性动作，无观测噪声；
  - 终止条件与 V3 统一评测相同。
- **所有方案都报：** 完成率、进度、物体位置 RMSE、身体与手的跟踪误差。
- **A–C 另报：** SONIC 跟踪误差和摔倒率。
- **训练速度（C 对 D）：**
  - 主指标：每个 checkpoint 在 ±2 档上的完成率，比较达到 50% 和 80% 所需的迭代数；
  - 辅助指标：奖励中跟踪部分的曲线、GPU 小时。
  - 详见 T03。
- **承重：** 质量扫描，Pull、Table、Bin 三个任务，每个从原质量起翻倍三次。见 T04。
- **尺寸：** Table Transport 的物体缩放 0.8 和 1.2 倍，用我们的流程重新生成参考。见 T05。

## 统计口径（预登记，不看结果后再改）

- **A、B：** 确定性方案，每档报 50 个初始状态的完成率。
- **与 D 比较：**
  - 每个初始状态配对，分别与 D 的三个种子做精确双侧 McNemar 检验，三个 p 值都报；
  - 同时报 D 三个种子的平均完成率和标准差。
- **C 的主实验：** 每个任务有三个种子后，与 D 按种子配对比较，口径同论文 Table III；只有一个种子时，标明"初步、单种子"。
- **质量和尺寸扫描：**
  - 曲线统一用种子 721，原质量（原尺寸）点也用 721；
  - 原质量点另外标出 D 三个种子的范围。
- **剔除：** 只按 T03 写明的规则。所有回合都进表。
