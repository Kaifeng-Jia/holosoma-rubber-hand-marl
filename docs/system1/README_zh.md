# System 1 对比实验总览（2026-11-09）

## 要回答的问题

面向交互的多机器人快系统该怎么搭？三种选择：
- 分层：目标交给通用全身控制器执行；
- 端到端；
- 两者结合。

要回答的是：每种方式在什么条件下够用，在什么条件下不够。

## 四种方案

| 方案 | 关节目标由谁给 | 是否训练 | 反馈 |
|---|---|---|---|
| A 静态目标 + SONIC | SONIC | 不训练 | 无，开环 |
| B 动态目标 + SONIC | SONIC | 不训练 | 规则闭环 |
| C MARL + SONIC | SONIC | 训练高层 | 学习闭环 |
| D 端到端 MARL | 策略本身 | 训练 | 学习闭环 |

- **A：**
  - 每台机器人各用一个 SONIC 实例：权重共享，批量推理。
  - 输入是该机器人的 DuetMimic 参考（全身关节轨迹和根位姿）。
  - SONIC 不观测物体。
- **B：** 在 A 的基础上，每一步按物体的实际位姿重算手的目标。
  - 参考里手相对物体的位置保持不变，目标跟着实际物体走。
  - 再把手目标沿接触法向往物体内侧偏一段距离。偏移量取 0、2、4 cm 三档，全部报告。
  - 原因：没有力接口的控制器，只能靠"目标陷进物体"来产生压紧力。
- **C：** 用 MAPPO 训练高层，输出对 SONIC 输入目标的修正量，SONIC 冻结不动。
  - 奖励、并行环境数、迭代预算、种子都与 D 一致。
- **D：** 现有 DuetMimic，直接用论文里的 checkpoint 和训练记录。

## 评测与指标

- **评测协议与论文相同：**
  - 每个任务 50 个冻结初始状态，分 ±2 和 ±8 两档；
  - 确定性动作，无观测噪声；
  - 终止条件与 V3 统一评测相同。
- **所有方案都报：** 完成率、进度、物体位置 RMSE、身体与手的跟踪误差。
- **A–C 另报：** SONIC 的跟踪误差和摔倒率。
- **C 和 D 另报：**
  - 训练曲线；
  - 达到同一奖励所需的迭代数和环境步数（主口径）；
  - GPU 小时（辅助口径，注明硬件）。
- **承重：** 扫物体质量。Table Pulling 取 5/10/20/40 kg，Table Transport 取 2.5/5/10/20 kg，详见 T04。
- **尺寸：** 在 1 个任务上缩放物体，用现有重定向流程重新生成参考。见 T05，任务书另发。
