   - 用 `taskset` 或 `numactl` 把每个进程绑定到各自的核上。
   - 记录机器的总核数，以及每个进程分到的核数。
2. **每步的 GPU→CPU 同步。**
   - 查 rollout 循环里每一步都会触发同步的调用：`.item()`、`.cpu()`、`.numpy()`、在 Python 里判断张量的条件等。
   - telemetry 和日志统计改为在 GPU 上累积，每轮只同步一次。
3. **只用于日志的诊断量。**
   - 例如 Bucket 的接触、高度、相对关系诊断：这些不进奖励，但每步都在算。
   - 能确认它们不进 reward、终止条件、观测的，改为只在记日志的那一轮计算。
   - 改之前，用源码和测试证明它们确实不参与训练。
4. **一张卡跑多个 run。** GPU 利用率明显低于 100% 时，测一张卡同时跑 2 个 run 的总吞吐和单 run 速度，取总吞吐更高的方案。

**明确禁止，以保证消融和已有 Full 结果可比：**
- 不改：环境数、每轮步数、迭代数、物理/控制频率、学习率、PPO 参数；
- 不开混合精度；
- 不改网络结构。
