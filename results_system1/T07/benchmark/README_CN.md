# T07 第 3 步：带手 D 的速度、显存、CPU 基准（云端 4090）

## 做了什么

- **训练：** 带手 D，手指 learn 模式，Bin 任务，2048 个环境，每个环境每轮 24 步，跑 100 轮，种子 721–723。
  - 命令：`scripts/train_core4d_smalltable.py --experiment bucket003 --reward-variant bucket_A_no_rel_no_height --num-envs 2048 --steps-per-env 24 --iterations 100 --finger-mode learn --hand-reference logs_system1/t06/reference/test_A_track.npz`
  - 手指参考用 T06 第 2 步的测试参考（sha256 aca0cfc5…）。正式参考还没定；手指参考只影响目标值，不影响计算量。
- **机器：** 云端 AutoDL，5 × RTX 4090（24 GB）。
  - CPU 为 Intel Xeon Platinum 8352V，基频 2.1 GHz，最高 3.5 GHz，128 个逻辑核；cgroup 配额 80 核。
- **代码：** 训练脚本、`system1/hand/*`、bucket 奖励、plan5 manager 的 sha256 和本仓库 8239873 一致，逐个文件核对过（`bench2_code_sha256.txt`）。
- **四种情况：**
  1. 第一次测量（17:5x）：GPU 0，同卡上有 1 个曲线评测，那个评测中途结束。
  2. 独占：GPU 1 上只跑 1 个。
  3. 一卡 3 个 2048：GPU 2 上隔 30 s 依次启动 3 个。第 2 个启动时 CUDA OOM 退出，实际是一卡 2 个。
  4. 一卡 3 个 1024：GPU 3 上 3 个，各 1024 个环境。这一项是 3 × 2048 放不下以后加测的，不改正式配置。
- 第 2–4 种同时在 GPU 1–3 上跑，CPU 总用量约 20 核，在配额以内。
- **监控：** 每 10 s 记一次进程显存、整卡显存和利用率。
  - CPU 核数取上 10 s 内进程 utime+stime 的增量；第一次测量记的是 ps %cpu（进程生命期平均）。
  - 每轮秒数取第 11 轮起的中位数（前 10 轮含启动）。

| 独占 | 2048 | 91（崩溃，见下） | 15.93 | 3085 | 3085 | 9820 MiB | 9833 MiB（崩溃前） | 2.66 |

- 橡胶手 D 独占时是 5.29 s/轮。带手 D 独占时 15.93 s/轮，约慢 3 倍。
- 独占时 GPU 平均利用率 27%，每个 run 只用约 2.7 个 CPU 核。
- 一卡 3 个 1024 时整卡利用率约 87%。
- 一卡放 3 个 2048 放不下。2048 个环境的进程显存约 9.4–9.8 GB，1024 个约 6.3 GB。
- 详细数字在 `benchmark.csv`。

## 训练中途崩溃（7 个 run 里 2 个）

- **哪两个：** 独占的种子 721 在第 91 轮后，一卡 2 个里的种子 721 在第 65 轮后。
- **报错：** 采样动作时 `RuntimeError: normal expects all elements of std >= 0.0`，位置是 `holosoma/agents/modules/ppo_modules.py` 的 act。
- **为什么这样报错：** 那里 std 的写法是 `mean * 0.0 + self.std`。只要任意一个环境的动作均值是 NaN 或 inf，std 就是 NaN，报的就是这个错。
- **崩溃前的情况：**
  - 最后几轮的 metrics（奖励极值、熵、KL、梯度范数、失败数）都正常，也都是有限值。
  - 进程显存在崩溃前最后一次记录里突然增加：独占 9820 → 18832 MiB，一卡 2 个 9820 → 14444 MiB。
  - 日志里没有 PhysX 报错。
- **其他 run：** 另外 5 个跑满 100 轮（含第一次测量），没有崩溃。另有 1 个是启动 OOM，不算在这里。
- 橡胶手 D 的训练没有出现过这个错误。
- 原因还没查实。处理方式（例如定位是哪个环境、哪个物理量先变成非有限值，或者把状态非有限的环境重置掉）会涉及终止条件，等 Kevin 决定。
