## 2. 怎么量的

和 `palm_gap_check.py` 同一套，逐帧算 30 Hz 的求解结果。

- **构造：**用 prediag 自己的加载函数重建 `frontback.build(..., turn="world", legs="mirror", walk_distance="pelvis_feet")`，和求解文件对照。人的关节差 ≤ 8.2e-9 m，共享箱子 P 差 0。
- **机器人掌心：**橡胶手掌心点，用求解自己的 `scene_sim.xml` 做 MuJoCo 正运动学，量到共享箱子的有符号距离，正值表示在箱外。
- **机器人碰的面：**手的仿真碰撞外壳和箱子之间的精确最近点（`mj_geomDistance`），这个点落在共享箱子的哪个面上。也就是 palm_gap 里的 `hull_contact_face`。
  - 13 条 52 只手的外壳到箱子距离，中位数都是 −0.10 cm，即求解的防穿透下限 −1 mm。所以四只手都贴着箱子。
- **人那只手所在的面：**人的掌心点在人实际抱的那只箱子上离哪个面最近。
  - 机器人 1 对应的"人"是镜像副本，即镜像过来的示范者另一只手。
  - 这个面要换到机器人的共享箱子上，才能和机器人碰的面比。我报了三种换法：
    1. **按标签**，即构造本身的对应关系。构造规则 3 抬平箱子时保留箱子的轴：长轴 k 转到走路方向，第 0 帧竖直的轴保持竖直。人实际箱子的面 (轴, 正负) 就是抬平箱子的同一个面，再经 M0（机器人 0）或 M1（机器人 1）的转动部分换到共享箱子。sigma−1 的片段 M0 = diag(−1, −1, 1)，所以人那边的 ±x、±y 标签不能直接拿来比。
    2. **按几何方向：**把实际箱子那个面的朝向经交互网格的映射带过去。这样会包含实际箱子相对抬平箱子的偏航和倾斜，偏到 45° 左右时会跳到另一个面。
    3. **交互网格目标点：**人掌心这个点经交互网格的映射落在共享箱子里，它离哪个面最近。也就是 palm_gap 里的 `im_target_nearest_face`。
  - 判定：三种换法得到同一个面时，机器人碰的面和它相同记"对应"，不同记"不对应"；三种换法不一致时记"人这边不一致"。
- **面的名称：**从每台机器人自己面向箱子的方向看。
  - 左侧、右侧；
  - 近端：朝自己的端面，也就是搬运轴 k 上靠自己这一头；
  - 远端、顶面、底面。
  - 箱子坐标系里的 ±x / ±y / ±z 标签见 CSV。
  - 换成按机器人骨盆方向判面，和按 k 轴判面在 52 只手的所有帧上都一致。
- **距离：**用中位数（全片段所有帧）。
  - 主表里是机器人掌心到它碰的那个面（有限矩形）的距离。
  - CSV 里另有：机器人掌心到人那个面、人掌心到人实际箱子（有符号）、人掌心到机器人碰的面。
- **核对：**sub8_suitcase_020 1.00 的 240 行逐帧数值和面，和 `palm_gap/palm_gap.csv` 完全相同（差 0，面不一致 0 帧）。
