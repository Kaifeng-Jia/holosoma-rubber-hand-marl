  - T10 的 MuJoCo 场景同样按 `average` 设：机器人对物体 0.75。

**组合方式实测（`combine_mode_test/`）**

- **场景：** 一个最小场景，不是评测场景。写材质的两条路径和评测相同：
  - "手"：一个固定底座、只有一个连杆的关节体，是一块平板，没有绑定 USD 材质。摩擦用 `Articulation.root_physx_view.set_material_properties` 写，和 `system1/t10b/hand_material.py` 相同。
  - "物体"：一个放在平板上的 `RigidObject` 扁盒（0.3 × 0.3 × 0.1 m，1 kg），也没有绑定 USD 材质。摩擦用 `RigidObject.root_physx_view.set_material_properties` 写，和 holosoma 的 `set_object_rigid_body_material_startup` 相同。
  - 写入顺序和评测一样：先写物体，再写手。写完都读回核对过。
- **场景级物理设置：** 按上面导出的 `scene.json` 设：
  - dt 1/200，TGS，场景默认材质 1.0 / 1.0 `average`，地面 1.0 / 1.0 `multiply`，重力 9.81；
  - bounce threshold 0.5，friction offset threshold 0.04，friction correlation distance 0.025，不开 stabilization 和 CCD；
  - 关节体求解迭代 8 / 4，刚体 16 / 1，GPU PhysX。
- **测法：**
  - 盒子在平板上静置 100 步，然后给它一个水平初速度，1.0 或 2.0 m/s。
  - 对滑动段的速度做直线拟合，从推后第 3 步起，到速度降到初速度 10% 为止。
  - 摩擦 = −加速度 / g。静、动摩擦设成相等，所以测到的是组合后的动摩擦。
- **对照组：** 平板和盒子都绑定 USD 材质，组合方式已知（average、min、multiply、max），不用 tensor API 写。手 0.75、物体 0.5，四种方式的预测值都不同：0.625、0.5、0.375、0.75。

## 2. 终止原因

**判定规则：**
- 评测器只记录 `joint_bad_tracking` 触发了，不记录是其中哪一条，所以从轨迹判断。
- 看最后一行记录的物体，和终止判定时用的那一帧参考比：
  - 位置误差 > 0.25 m，记为物体位置；
  - 否则姿态误差 > 0.8 rad，记为物体姿态；
  - 否则记为机器人姿态，因为躯干倾斜不在轨迹里。
- 实现在 `system1/t10b/phases.py` 的 `termination_errors`、`termination_reason`。

| 方案 | 任务 | 手 0.75：失败（物体位置 / 物体姿态 / 机器人姿态） | 手 0.5：失败（物体位置 / 物体姿态 / 机器人姿态） |
|---|---|---|---|
| D | Bin | 19（19 / 0 / 0） | 8（7 / 1 / 0） |
| D | Table | 5（4 / 1 / 0） | 17（1 / 16 / 0） |
| D | Pull | 1（1 / 0 / 0） | 1（1 / 0 / 0） |
| D | Chair | 9（2 / 7 / 0） | 1（0 / 1 / 0） |
| D | Push | 36（36 / 0 / 0） | 28（28 / 0 / 0） |
| D | Kick | 0 | 0 |
| C-in | Bin | 56（53 / 3 / 0） | 150（145 / 5 / 0） |
| C-in | Table | 37（33 / 4 / 0） | 24（24 / 0 / 0） |
| C-in | Pull | 40（40 / 0 / 0） | 49（49 / 0 / 0） |

**"终止判定时用的那一帧"：**
- 评测器在轨迹第 k 行记录的参考帧是 `reference_frame` = k。终止项比对的却是动作指令当时的帧 `reward_reference_frame`，也就是 k − 1。
- 在本次 2754 个回合上核对过：
  - 按 k − 1 比：497 个失败回合的最后一行全部超过物体位置或物体姿态阈值，之前的行都没有超过；完成的回合没有一行超过。
  - 按 k 比：239 个失败回合在终止前就有某一行"超过阈值"，和"超过就终止"矛盾。
- **和之前的偏差：**
  - 本脚本最初的规则用的是第 k 帧。按那个规则，本次会有 100 个失败回合被记为机器人姿态，其中 C-in Bin 0.5 有 69 个。
  - 同一规则也用在了已推送的试点进度返包（`retrain/pilot_progress/`，`5f420d9`）第 3 节。那里会按更正后的规则重算。
- 物体误差第一次超过 0.1 m 的那一步，见第 3 节。它仍按评测器自己的对齐方式算，即第 k 行对第 k 帧，和 `object_rmse`、T10s 相同。
