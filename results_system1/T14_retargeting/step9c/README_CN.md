## 3. 第一次运行发现的实现错误，以及修正（第二次运行）

**现象：**
- 第一次运行和第 9b 步里，副本机器人在第二阶段从第 0 帧起就转过身（和它的初解差约 190°），离它要跟的人 0.57–0.71 m，站在箱子中段，朝向和原示范相同。
- 副本自己的第一阶段初解是对的：骨盆离人 0.01–0.09 m。
- 结果：副本全程有非手部位穿透（9c 第一次运行 125 / 125、128 / 128、135 / 136 帧，深 7–8 cm，躯干、骨盆、髋），以及两机相交。

**原因：**
- `role_solve.py` 第二阶段的交互网格里，人一侧的拉普拉斯坐标在"这个角色自己的物体"坐标系里算，机器人一侧在共享目标盒坐标系里算。
- 拉普拉斯坐标对平移不变，对转动会变。
- 原示范一侧两个坐标系只差平移（sigma = +1），所以没事；副本一侧差一个 180° 转动，机器人就照搬了"原示范对近端"的相对关系。

**修正（`--fb-human-frame target`）：**
- 人一侧的物体坐标系改为"自己的物体乘以本角色的区域映射的逆"，物体点改为 M_r 作用后的点；世界里的点不变（代码里有断言检查）。
- 这样人一侧和机器人一侧只差平移，以及取中点带来的小转动（和原示范一侧一样）。
- 原示范一侧 sigma = +1 时 M0 只是平移，所以结果不变。
- 3 帧验证（`logs_system1/t14/step9c/debug/`）：修正后副本骨盆在 y = −0.364 m（人 −0.337 m，初解 −0.324 m），修正前在 +0.229 m。

**第二次运行**只加了这一处修正，另外把搜索规则补全为：1.5 倍求解失败、而 1.0 或 1.25 倍相交时，照样往上搜，并越过失败的档。第一次运行里我对 smallbox 就是手动这样接着搜的（`run1/records/search_up.json`）。
