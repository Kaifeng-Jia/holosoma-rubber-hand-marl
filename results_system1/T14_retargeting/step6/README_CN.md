## 1. 本轮做了什么

### 1.1 支撑脚（所有任务一套）

- **支撑帧判定：**人脚尖（CORE4D 用 L_Foot / R_Foot，OMOMO 用 L_Toe / R_Toe，同求解器原来所用）水平位置先做高斯平滑（σ = 8 帧，30 Hz），再算速度，< 0.01 m/s 为支撑；第 0 帧不算支撑（同原代码）。代码 `system1/t14/support.py`。
  - 平滑的原因：不平滑时，CoCarry 原口径把支撑段切得很碎（速度最慢的 10% 帧仍有 1.2–2.6 cm/s）。
  - 支撑帧占比和段数记在每个求解的 run_record（`records/solve__*.json` 的 `foot`）。
- **约束：**支撑脚锁在这段支撑开始时的位置，x、y 各 ±1 mm，不再相对上一帧。
  - 求解器每只脚约束 5 个脚底球连杆；每个连杆各自锁在本段开始时的位置（本段第一帧求解时，上一帧已求出的该点位置）。
  - 弹性松弛和权重沿用原设置（脚 1e4），脚高约束（±5 mm）不变。
  - 实现：底座加一个钩子 `foot_sticking_reference`，不设时行为不变；`palm_retargeter.enable_stance_lock`；开关 `--foot-cocarry`。
  - 第一次冒烟时 5 个连杆共用了一个锚点（写错），Push 脚尖漂移仍有 1.6–2.5 cm；改成每个连杆各自的锚点后为 0.16–0.26 cm，然后重开。冒烟测试 `system1/t14/test_support_stance.py`。
