# T03 返包：C 第二版主实验（原质量，橡胶手）

## 做了什么

- **评测：** 原质量下各 run 的最终 checkpoint，±2、±8 两档，各 50 个冻结扰动状态加 1 个 nominal。
  - 确定性动作，TF32 关闭，全部在本机 RTX 5070 Laptop 上评测（论文主对比表用的卡）。
  - 不挑 checkpoint、不挑回合，所有回合都进 `episodes.csv`。
- **run：**
  - C-in：种子 721、722、723；
  - C-out：种子 721；
  - D：论文主结果，种子 721、722、723，在本机重评。±2 用流水线 d_curve 对最终 checkpoint 的评测，±8 用 d_paper_final。
  - 迭代数：Pull 第 8050 轮，Table、Bin 第 12000 轮。
- **冻结状态：** 同一任务、同一档位的所有方案和种子都用同一个状态文件，打包时逐一检查了 sha256。
- **打包：** 由 `system1/t03/package_c2.py` 从已有评测输出汇总，只读，在 CPU 上运行。
  - 每回合的字段沿用 V3 收尾包 `results/episodes.csv`，新增 `scheme`、`seed`、`gpu_model`、`sonic_fell_any`。
  - 手误差、掌心误差的算法和 T04 返包相同。
  - `evaluation_code_sha256` 取每次评测启动记录里那个 git 提交中的评测脚本。
- **统计（预登记口径，`docs/system1/README_zh.md` 的"C 的主实验"）：** C 与 D 按种子、按初始状态配对，做精确双侧 McNemar 检验，nominal 不进配对。
  - C-in 对 D：3 个种子合并成 150 对（同论文 Table III），另外每个种子单独 50 对，所有 p 值都报。
  - C-out 只有种子 721，和 D 的 721 配对，标"单种子，初步"。

## 文件

- `episodes.csv`：2142 行，即 42 个评测 × 51 回合。
- `per_seed_summary.csv`：每个（任务、方案、种子、档位）一行，含 checkpoint、状态文件、summary 的 sha256，以及 GPU 型号。
- `scheme_summary.csv`：各方案在种子间的均值和样本标准差。
- `mcnemar.csv`：上表的全部比较。
- `provenance.json`：每个评测的来源目录、参考的 sha256、手正运动学自检、掌心后处理脚本的 sha256。
- `configs/`：12 个 C run 的训练记录，均来自云端。
  - `*.run_config.json.gz`：完整 run_config，gzip 压缩，解压后的 sha256 和云端原文件一致；
  - `*.run_config_diff.json`：和 D 对照配置的差异，每个 run 都是 `n_unexpected` = 0；
  - `*.launch.json` / `*.exit.json`：启动和结束记录。
- `SHA256SUMS`。

生成命令：

    hssim_s1/bin/python -B system1/t03/package_c2.py

## 和任务书的偏离

- C-out 只有 1 个种子，按任务书标"单种子"。
- 训练曲线、首次达到 50% / 80% 的迭代数、曲线下面积和每轮用时，单独成包，不在本包里。其中 Table、Bin 第 9000–12000 轮的点正在云端补评。
