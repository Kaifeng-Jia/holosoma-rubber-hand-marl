## 三个问题的答案

1. **来自哪一项奖励：日志不足以唯一确定。**
   - 这条训练路径（CORE4D 双人，Table、Bin）的日志没有分项奖励。Pull 的 `reward_terms_raw_mean` 是 rollout 结束时的一次快照，也定位不了。
   - 按各项的定义可以排除：
     - 6 个运动跟踪项是 exp 形式，在 [0, 1] 内；
     - undesired_contacts 是个数；
     - bucket 交互项尖峰那一轮的 `Bucket/raw_reward_min` 在 0.25–0.77，属正常。
   - 能到这个量级的只剩两个无界惩罚项：`action_rate_l2`（权重 −0.1，算动作每步变化的平方和）和 `limits_dof_pos`（权重 −10，算关节超出软限位的量）。
   - 按数量级推断，**很可能是 action_rate_l2**。奖励按 dt = 0.02 缩放，第 8882 轮那一个样本：
     - 若是 limits_dof_pos，关节要超出限位约 1e16 rad；
     - 若是 action_rate_l2，动作每步变化约 1e8 就够了。C 计入这一项的是由 SONIC 输出换算来的原始动作，不截断；D 是策略的原始输出；两边的观测都不截断，物理状态发散时这些动作会跟着放大。
   - 这是推断，没有分项日志证实。
2. **哪个环境：日志没有记录。**
   - Table、Bin 的训练只记了每轮的汇总量，没有逐回合遥测（只有 Pull 有 `episode_telemetry.jsonl.gz`）。
   - 能确定的是：每次极端尖峰都只来自一个环境的一步，是第二台机器人。
3. **发生了什么：**
   - 某个环境里，第二台机器人的身体相对物体的位置误差在一步之内变成约 8e2 m 到 6e14 m（假设只有一个样本，由向量误差均值 × 49152 再开方得到），也就是这台机器人的物理仿真发散了。
   - 这个环境随后被重置。下一轮训练统计全部恢复正常，前后 100 轮的训练表现没有可见变化。
   - 只出现在 Table 任务上。C-in 的 4 个 Table run 共 7 次（含 10 kg）；D 论文 Table 的三个种子里，723 出现过 1 次，特征相同。C-out Table 和所有 Bin run 都没有出现。
