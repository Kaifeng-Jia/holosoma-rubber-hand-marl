# T03 训练效率（第 5 项）

依据：`docs/system1/T03_schemeC_marl_sonic_zh.md` 里"训练速度"的预先规定。曲线点全部来自云端 RTX 4090（Kevin 2026-11-12），`docs/system1/paper_results_plan_zh.md` 第三次修订。

## 做了什么

- 对每个保存的 checkpoint，在冻结的 ±2 初始状态（50 个扰动状态，加 1 个名义回合不计入）上评完成率，C、D 都评。
  - 评测是确定性的，TF32 关闭。
  - 评测程序：`scripts/evaluate_paper_supplement.py`。
- 由 `system1/t03/train_efficiency.py` 汇总（只用 CPU、只读）。
  - 读取同步回本机的云端评测 `exports_system1/cloud_sync/logs/evals/{c2_curve,d_curve}/` 和训练日志 `metrics.jsonl`。
  - 没有手填的数字。
- 环境步数 = 迭代数 × 49152（2048 个环境 × 每次迭代 24 步，各 run 的 run_config 一致）。
- 每个 run 的指标：
  - 第一次完成率 ≥ 50% 和 ≥ 80% 的 checkpoint（迭代数、环境步数，没达到写 "not reached"）；
  - 曲线下面积：评过的点之间用梯形法积分，再除以迭代跨度，等于跨度内的平均完成率（%）；
  - 最后一个点的完成率。
- 墙钟时间：`metrics.jsonl` 的 `elapsed_seconds`，取第 101 轮以后每轮秒数的中位数，加上总小时数。

## 曲线点

- **共 236 个点，全部 complete，全部在 RTX 4090 上评**：Pull 90 个，Table 73 个，Bin 73 个。现在没有缺点。
- **其中 34 个是在云端曲线截止之后补评的**（见 `results_system1/T03/curves_end/`）：
  - 28 个 C 主曲线点。Kevin 2026-11-13 22:1x 同意补评。启动器 `system1/cloud/run_curve_points.py`，22:15:03 开始，2026-11-14 01:17:04 全部结束。
  - 6 个 D Bin 种子 721 的点（第 0、2000、4000、6000、8000、10000 轮）。这 6 个原来不在云端 D 曲线清单里。Kevin 2026-11-13 23:0x 同意补评，23:10:22 开始，2026-11-14 01:16:22 全部结束。
  - 34 个点的评测命令、环境和记录方式，都和云端调度器自己的评测一致。
- 8 个 C 主曲线第 12000 轮 ±2 的点，原先由本机认领（本机的最终评测）。这次在云端重评，认领仍归本机，另外写了 `cloud_rerun.json`；曲线用云端的数。

## 墙钟时间（`wallclock.csv`）

- C（C-in、C-out，全部 run）：云端 RTX 4090，每轮 8.6–9.9 s（中位数）。
- T04 重训的 D（种子 721，6 个 run）：同一批云端 4090，和 C 同时训练，每轮 8.75–9.81 s。
- 论文 D 的 run：每轮 2.5–7.0 s，但训练记录里没有 GPU 型号和同时运行的任务数。所以它和 C 的墙钟时间不能直接比，表里 GPU 一栏留空。
