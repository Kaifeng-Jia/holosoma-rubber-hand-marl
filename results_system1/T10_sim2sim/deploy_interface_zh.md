# 真机接口说明：C-in 怎样接上官方 SONIC 部署（T10 第 4 步）

只写接口和待确认的问题，不含部署代码。依据：官方仓库 `NVlabs/GR00T-WholeBodyControl`（本机拷贝 1e1ec4f）的 `gear_sonic_deploy`、`gear_sonic/utils/mujoco_sim`、`docs/source/tutorials/zmq.md`，以及本次 MuJoCo sim2sim 的实现（`system1/sim2sim/`）。设置的逐项对照见 `settings_compare.md`。

## 1. 每台机器人上的进程

两台机器人各跑一套，彼此独立。

| 进程 | 来源 | 频率 | 输入 | 输出 |
|---|---|---|---|---|
| SONIC 部署 `g1_deploy_onnx_ref` | 官方，C++ | 输入线程 100 Hz；控制线程 50 Hz（编码器和解码器推理）；planner 10 Hz（我们不用）；电机指令 500 Hz | Unitree LowState（IMU 四元数和角速度、29 个关节的位置和速度，DDS）；参考：运动文件，或 ZMQ 流 | LowCmd：每个电机的 q 目标、kp、kd、dq=0、τff（DDS，500 Hz 重发最新目标） |
| C-in 协作层（我们的） | 待写 | 50 Hz，和 SONIC 控制线程同频 | 158 维观测（见第 2 节） | 29 维修正 dq；转成修正后的参考，发给 SONIC 部署（见第 3 节） |
| 状态 / 定位服务 | 待定（动捕） | ≥ 50 Hz | 两台机器人骨盆的世界位姿；物体位姿（只用于判定和记录，策略不看物体） | 每台机器人的根位置、朝向、质心线速度；同伴的相对平面位置和速度 |

- **低层：** 真机由电机驱动器执行 PD。
- **sim2sim：** 官方 MuJoCo 仿真用 τ = τff + kp(q* − q) + kd(0 − q̇)，按电机力矩上限截断，200 Hz。
- **我们的 Isaac 训练：** 公式相同，每个 200 Hz 子步算一次。

## 2. 需要的外部信息

C-in 的 158 维观测按 holosoma 观测管理器的字母顺序拼接：

| 项 | 维数 | 真机上的来源 |
|---|---|---|
| 上一步动作（截断到 ±1） | 29 | C-in 自己 |
| 骨盆角速度，骨盆系 | 3 | IMU |
| 关节位置 − 默认姿态、关节速度 | 29 + 29 | 关节编码器（LowState） |
| 参考关节位置和速度（当前帧，未加修正） | 58 | 参考文件 + 同步的帧号 |
| 参考躯干朝向在实际躯干坐标系下的旋转矩阵前两列 | 6 | 需要躯干在**参考世界系**里的完整朝向，包括偏航角。IMU 的偏航会漂，需要动捕或其他绝对航向 |
| 同伴根的相对平面位置（观察者航向系） | 2 | 两台机器人的根位置，来自动捕 |
| 同伴根的相对平面速度（观察者航向系） | 2 | 两台机器人根的**质心线速度**（Isaac Lab 的 root_state 约定），需要由动捕估计；训练时截断到 ±1 |

- **参考时间同步：** 两台机器人和物体共用一个参考时钟。
  - 训练时，两台机器人在每个控制步 k 读同一个参考帧 k。
  - 真机上需要同一个起始触发，以及共同的帧号。ZMQ 消息本身就带全局 `frame_index`。
- **起始站位：**
  - 两台机器人按参考第 0 帧的根位姿摆放，训练和评测只覆盖 ±2 cm / ±2° 和 ±8 cm / ±8°。
  - 物体按参考第 0 帧摆放。
  - 需要把参考世界系和动捕世界系对齐。
- **不需要的：** 策略不看物体状态。物体位姿只用于判定是否完成，以及安全上的中止条件。

## 3. C-in 怎样接上官方 SONIC 部署

在 Isaac 里，C-in 每一步把同一个 dq 加到 SONIC 参考窗口的每一帧关节位置上，再按关节限位截断。窗口是 10 帧、每隔 5 帧（0.1 s），向前看 0.9 s。官方部署的 g1 编码器用的是同一个窗口，关节顺序、拼接顺序也相同（`command_multi_future_nonflat` = 290 个位置 + 290 个速度；`motion_anchor_ori_b_mf_nonflat` 10 × 6）。所以 C-in **不需要重训**，有两条接法：

1. **ZMQ 协议 v1（逐帧发整身参考）。**
   - 每个控制步，C-in 进程把从当前帧起至少 46 帧（覆盖 +45 帧）的参考打包发出：
     - `joint_pos` = 参考 + dq，按关节限位截断，IsaacLab 顺序；
     - `joint_vel` = 参考，不改；
     - `body_quat` = 参考根四元数，wxyz；
     - `frame_index` = 全局帧号。
   - 部署端的 `StreamedMotionMerger` 从新一段的第一帧起覆盖已收到的数据，所以每步重发会刷新整个窗口。
   - 部署端用的是官方编码器，和本次 sim2sim 用的是同一个 ONNX 文件。
2. **ZMQ 协议 v4（直接发 64 维 token）。**
   - C-in 进程本地按第 1 种方式组好窗口，自己跑官方 `model_encoder.onnx`，把 token 发过去；部署端只跑解码器。
   - 本次核对：官方编码器 ONNX 的 token 和我们 Isaac 用的 `last.pt` 逐元素相同。

**和训练不一致、还差的地方：**

- **航向补偿。** 部署端算参考朝向时，先把参考乘以"机器人初始航向 × 参考初始航向的逆"，也就是把参考对齐到机器人的起始航向。Isaac 里没有这一步：参考和机器人在同一个世界系，起始航向本来就一致。
  - 起始航向一致时两者相同；
  - 不一致时，C-in 看到的参考朝向（第 2 节第 5 行）和 SONIC 看到的会不同。需要约定一个共同的世界系。
- **默认姿态。** 部署端的 `default_angles` 是取到三位小数的值，和 SONIC 训练环境的默认姿态最大差 0.01 rad。SONIC 的目标 = 默认姿态 + 缩放 × 动作，所以这个差会直接加到真机的目标上。
- **力矩上限。** C-in 训练时用的是我们 URDF 的力矩上限，例如髋 roll 139 Nm；官方 sim2sim 和电机的上限是 88 Nm。本次 MuJoCo 的设置 (ii) 用了官方上限，结果见 README。
- **手。** 训练用橡胶手（固定在腕上，无自由度）；官方 sim2sim 是 Dex3 三指手（每只 7 自由度）。真机装什么手决定了接触和质量，需要先定。
- **时延。** ZMQ、动捕、推理的时延在训练里没有建模。训练时策略在 50 Hz 下没有动作延迟。
- **流的余量。** 窗口要看 0.9 s 以后的参考，流必须始终领先播放游标 ≥ 45 帧；部署端有 `MAX_GAP_FRAMES = 200` 的追赶重置。需要确认 C-in 的帧号和部署端播放游标怎样对齐，以及 `catch_up` 怎样设置。
- **起停顺序。** 部署端需要按键 `]` 启动、`ENTER` 切到 ZMQ 模式、`O` 急停。两台机器人要同时进入跟踪；按键流程需要脚本化。

## 4. 要和博士生确认的问题

- **机器人：** 几台 G1，型号是 29 自由度的 EDU 吗？腕部是否 3 自由度（我们的模型是）？
- **手：** 能否装橡胶手（和训练一致），还是只有 Dex3 或其他手？如果换手，要重新做哪部分验证？
- **动捕：** 什么系统，频率多少、延迟多少、覆盖范围多大？能否同时跟踪两台机器人的骨盆和躯干，以及物体？
- **航向：** 起始时用动捕给两台机器人和参考定一个共同的世界系，可以吗？
- **计算：** C-in 和 SONIC 部署跑在机器人上的 Orin，还是外部电脑？两台机器人的 DDS 域、网卡怎么隔离？
- **安全：**
  - 吊架或保护绳，两台机器人各一套？
  - 急停：两台机器人分别有硬件急停吗？软件急停（部署端按键 `O`）由谁触发？
  - 中止条件：比如物体偏离参考 > 0.25 m，或躯干倾斜（训练时的终止条件）时，自动停止。
- **任务：** Table Transport（5 kg）还是 Bin（1 kg）？桌子或桶的复制品能否做到同样的质量、尺寸和摩擦？
- **场地：** 地面材质和摩擦；两台机器人和物体的起始摆放怎样标定（±2 cm / ±2° 以内）。
- **学校和时间：** 在哪所学校做，哪段时间能用机器人，有没有远程看实验的方式（视频、日志）。
